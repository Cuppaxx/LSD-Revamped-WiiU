## LSD: Revamped -> Wii U port plan

Status 2026-11-11: research done, source cloned, no code written yet.

## Facts
- Source: https://github.com/Figglewatts/LSDRevamped (MIT). Cloned (shallow, LFS included) next to the port as `src/` (not part of this repository). About 9.7 GB on disk (5.4 GB `LSDR/Assets/Resources`, 1.2 GB `UnityEditor`, 2 GB `.git`). The 184 MB figure on GitHub excluded LFS content.
- Engine: Unity 2021.3.45. Unity has no Wii U target, so this is a native rewrite, not a recompile.
- C# gameplay code is about 17k lines in `LSDR/Assets/Scripts` (the per-folder `cat` counts below include Torii, a bundled helper library).
  Dream 1.3k, Entities 1.3k, Game 1.8k, IO 1.1k, Input 0.55k, Lua 1.4k, UI 3.2k, Torii 4.3k, Util 0.5k, Visual 0.3k, Audio 0.2k.
- Lua: 106 .lua files hold dream/object logic (`Resources/Original/LuaInclude/dreams.lua`, `train.lua`, per-dream scripts). Needs a Lua runtime (plain Lua 5.2/5.3 C source builds fine for ppc).
- Game data is the ORIGINAL PS1 file set shipped in `Resources/Original`: `STG00..STG03/*.LBD, *.SEQ`, `IMG1`, `IMG2`, `FILM`, `SND`, `ETC`, plus `OriginalDreams*.asset` (Unity YAML, dream graph and spawn map), `*SongLibrary.asset`. 745 wav files (~1.3 GB, music/SFX).
- Format readers already exist in MIT C#: https://github.com/Figglewatts/libLSD (LBD/TMD/TIM/TIX/ANM/etc.), plus LSDView and LMM-reversing. Port these to C.

## Architecture (C, wut + GX2)
- `tools/` (PC, Python): convert/pack data into a compact big-endian blob set (meshes, textures as GX2-friendly RGBA/palettized, dream graph as flat tables, wav -> 22 kHz mono ADPCM or streamed .ogg/stb_vorbis). Output goes to `sd:/wiiu/apps/lsdr/data/`.
- `src/`:
  - `lsd_formats` : C port of libLSD loaders (or consume tool output only; decide at M1).
  - `gfx` : GX2 renderer: PS1 look = vertex color, nearest sampling, no perspective-correct emulation at first, fog, 320x240-ish internal res scaled to TV, GamePad mirror.
  - `world` : tile map, collision, player controller (walk/look/link-to-dream), object instances.
  - `dream` : dream graph, day counter, texture sets, spawn map, flashbacks.
  - `lua` : Lua 5.3 + bindings mirroring `Scripts/Lua` and `Scripts/Bindings` API.
  - `audio` : AX voices, streamed music, SFX (reuse learnings from the gamestream/AX work).
  - `ui` : title, menus, journal (use bitmap fonts, no TextMeshPro).
  - `input` : VPAD + KPAD/Pro controller via wut, mapping from the Input System assets.
- Memory budget: Wii U app gets ~1 GB MEM2 in homebrew; keep one dream resident, stream music from SD.

## Milestones
1. M1: tools unpack one LBD (STG00/M000) and render it textured, flying camera, on Cemu/hardware. Boot skeleton + Makefile.
2. M2: player controller + collision on that map; GamePad/Pro input; music loop.
3. M3: dream graph, linking between maps, day/night palette, fog; first 3 dreams complete.
4. M4: Lua runtime + object scripts (the 106 .lua files), all entity types in `Entities/Original`.
5. M5: UI (title/menu/journal), save data, flashbacks/FILM video, remaining dreams.
6. M6: polish, perf pass, HBL/Aroma packaging (`.wuhb`).

## Open risks
- Entire object behavior is driven by Lua + Unity prefabs (14 .prefab, 14 .unity scenes). Need to extract per-object prefab data (mesh refs, colliders, animators) with a one-off converter; Unity YAML is text so this is tractable.
- Video (FILM/*.STR) decoding on PPC: probably pre-convert on PC.
- Cemu is the quick test loop (works for plain homebrew; per notes, no Aroma plugins), real hardware for final.
- Copyright: the repo bundles original game data. Keep it out of anything I redistribute; the port loads from a user-supplied folder on the SD card.

## M1 status (2026-11-11): done in Cemu, not yet run on hardware

## Texture fix (2026-11-11)
- Cause of the over-bright speckled stairs/walls: lit textured TMD primitives carry no vertex colour, and I gave them white (255), which the x2 modulate (128 = neutral) doubled and saturated. They now get 128 (`lsd.c`, `build_object`). Verified in Cemu: brick, checkered floor, bottle shelves and wood counter now look right. The atlas itself was fine (dumped to PNG and compared).
- Left as is, unverified against Revamped: untextured polygons use their vertex colour directly (PS1 behaviour); Revamped's shader doubles it. Revamped also picks one of four texture sets (TEXA..TEXD) per dream and applies fog; neither is done yet.

## Perf pass 1 (2026-11-11): multithreaded banded rasterizer
- Rendering is now two phases: `level_render` (main thread) transforms, clips and projects every triangle into two lists (opaque, 50% blended) in ONE traversal of the level (was two), then `raster_render` splits the 240 rows into 16-row bands that 3 threads (main + 2 SDL worker threads) grab dynamically; each band first paints its sky rows, then draws both lists restricted to the band. Same pixels as before (checked by screenshot).
- Cemu numbers, Natural World (about 1.5k triangles on screen): raster 5-6.5 ms with 1 thread -> 1.7-2.6 ms with 3; projection stays about 2 ms (single thread). Earlier single-pass-over-lists version was 12-15 ms (float inner loop) before the fixed-point rewrite.
- On the console worker threads are SDL threads (assumed to spread over the 3 cores; not verified). `data/threads.txt` (a single number 1-5) overrides the count on SD; log line `rasterizer threads: N` and per-second `project=..us raster=..us`.
- Next perf candidates: project in the worker threads too (split chunks), only re-transform when the camera moved, lower internal fill for full-screen walls, cache `env_apply_fog`.

## M4 batch (2026-11-11): graph, timer, songs, sky effects, water, grey man (all tested in Cemu only)
- Days and the dream graph: a day lasts the start dream's DreamLengthSeconds (STG00 180 s, else random 60-360 s) and keeps running across wall links. Wall links (1.7 s contact) go to a weighted random linkable dream and stay in the same day. When the timer runs out the screen fades to the colour of the chart zone, the day number increments and the next dream is read from the 19x19 graph (`graph` line in dreams.txt) at the position computed from this day's per-chunk contributions (`lgraph` per dream, DreamSequence.EvaluateGraphPosition: average + a third of the last, wrapped at +-9; a grey man contribution of (-10,-10) counts too). Entity contributions from interactive objects are not available yet (they come with the Lua objects), so only area contributions are used.
- Music: `song <style> <path>` lines from OriginalSongLibrary; one style per day, a random song of that style per dream, falls back to any available style. Test bundle holds only the standard style; `--music-all` copies all 745 wavs (~800 MB).
- Sky effects: sun(s) with optional sunburst, clouds, stars from the environment (random chances per dream load), drawn as projected discs/ellipses/points in the sky band pass (the originals are prefab meshes; these are approximations at the same positions).
- Water: `water.bin` per dream (tools/convert.py reads the UV-rect override assets, water-map and palette PNGs): triangles whose UVs fall in a rect are re-mapped to the water map, rendered with palette cycling (index = map.r - t*speed/20), alpha min(0.5, map.a) in the blend pass. STG02 has 2 materials, STG03 3.
- Grey man: `ETC/SYMSPY.MOM` (one untextured TMD object, uprighted with the prefab's rotation) spawns on even days with 1 in 12 chance in dreams flagged GreyMan, once per visit, on entering and every 20 units walked; walks at the player at 0.3 u/s from 10 units away, within 2 units a white flash (0.1 s in, 3 s out), his contribution (-10,-10), then he vanishes; 135 s lifetime.
- Test hooks in `data/start.txt`: `<dream> nolink cycleN log threadN daylenN grey at X Z` (not shipped).
- NOT DONE: animated objects and Lua behaviours. Findings: interactive objects live in the dream prefabs as entities with Lua scripts (106 .lua files) that drive Unity objects through MoonSharp proxies (transform, quaternions, async actions), and their meshes/animations are baked into Unity `.asset` files, not raw MOM/TOD. Needs (1) a Lua runtime (none installed; liblua would have to be added), (2) a converter for the baked meshes/animation clips, (3) a small game-object/transform layer with the LSD/Unity APIs the scripts call. Sizeable on its own; also gives the missing entity graph contributions, flashbacks and special days.
- Also not done: load time of big dreams (STG03 = 256 chunks) blocks for several seconds with just a LOADING frame; no savegame; journal/title screens; flashbacks; video endings.

## M8 (2026-11-12): the Additional Dreams mod (Cemu only)
14 more dreams from github.com/Figglewatts/LSDR-Additional-Dreams (MIT): Dreamscape, Amber Street, Concretorium, Power Station, School, Ziggurat, Trash Out, Forum, Leisure Centre, Mill, Belvoir, Pooley, Railway, Eastern. Baked by `tools/addl.py` (format: `tools/ADDL_FORMAT.md`), played by the same game loop as the originals.
- Data: `python -I ..\tools\convert.py ..\src content\data --copy` now also runs addl.py into the same dir (`--cell 8` by default, `--noaddl` skips, `--tex/--cell` passed on; needs the clone in `ref/LSDR-Additional-Dreams`): `dreams_addl.txt`, `ADD00..ADD13/{world.bin,amodels.bin}`, `ADDTEX/*.tex`, `ADDLUA/*.lua` (+ `include/dreams.lua`), `ADDSND/*.wav` (~28 MB more in the wuhb). No name clashes with STGxx.
- Dream table (`dream.c`): dreams.txt = dreams 0..13, then dreams_addl.txt appended = 14..27 (`DreamList.norig`, `Dream.set`). The mod's K links and its 19x19 `graph` are offset by 14 at load; `require` reads `LuaInclude/` or `ADDLUA/include/` by the dream's set; `GetDreamByName` searches the script's own set first (exact, then substring). New lines parsed: world/models/gate/gates/epath/startonenable/aobj/gcontrib/audio/ecol/mclips (particles ignored).
- How the two sets mix (Revamped plays one journal at a time; this is the port's own choice, option OPTIONS > ADDITIONAL DREAMS, default ON, saved as `addl`): ON = one pool. Wall links pick weighted among all linkable dreams of both sets; the day end looks up the graph position in both GraphSpawnMaps and takes one of the two cells at random (a cell only one map fills always gives that dream); day 1 (NEW GAME / CONTINUE on day 1) is a random FirstDay dream of the enabled sets (Bright Moon Cottage or Dreamscape, Revamped's GetFirstDream rule); graph contributions of both kinds (LBD areas of the originals; GraphContributor entities and LogGraphContribution of the mod) feed the same day. OFF = the originals exactly as before (mod dreams hidden from Dream Select, never picked). Mod scripts always link inside the mod (their own dream list). Dream Select lists the originals, a heading ADDITIONAL DREAMS, then the 14 (scrolling list, 14 rows). Save: `visited` already had 32 flags (14..27 = mod), new keys `addl`, `affine`; old saves read fine.
- Mesh worlds (`src/meshworld.c`): world.bin chunks with boxes, material table, textures from a global cache (`ADDTEX`, ARGB, the four 512x512 atlases shared). Texture set A-D by the original day rule (`pick_texset`). Drawn triangles with an edge > 1.25 units are split at load for drawing (the original stays collision-only) to keep the affine warp and fog of big floors sane. Collision: `cw_build_tris` over the solid triangles (same 1x1 grid; Dreamscape 85k solid triangles build in 25-45 ms in Cemu, ~6.5 MB) + entity colliders (`ecol` boxes/upright cylinders, only while the entity is live).
- Rendering: rasterizer got a generic texture path (`RTex`: any power-of-two size, wrap by mask, cutout a <= 25, real alpha blend, water palette cycling) next to the untouched VRAM-atlas path; `render_meshworld`: chunk box vs view distance (min(render distance option, fog end) + 1) and the frustum, then outcodes per triangle, back-face cull for cull-2 materials; the visible chunks are projected in parallel on all render threads (`raster_parallel`, per-thread triangle lists merged afterwards).
